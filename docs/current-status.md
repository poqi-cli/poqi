# poqi — Current Implementation Status

Developer-focused PostgreSQL CLI/TUI that optimises for WASD navigation, rapid schema browsing, and quick query experiments.

The command, workspace crates, and supported environment variables use poqi names.

---

## Product Snapshot
- **Audience**: Developers who want a fast terminal-first way to poke real databases (especially during AI/LLM prototyping).
- **License**: The [poqi No-Sale Source License 1.0](../LICENSE) permits internal business use, modification and free sharing with corresponding source, but prohibits sales of covered software and modified versions, including paid hosted access. Previously MIT-licensed material retains its MIT permissions even if the project moves to a new repository. See the [licensing summary](../README.md#license-and-responsibility) for scope and responsibility.
- **Platforms**: Windows, macOS, and Linux terminals with mouse + OSC-8 support where available. PR, `dev`, and `main` CI runs on Ubuntu with Docker-backed PostgreSQL tests. The release workflow targets Windows x64, Linux x64, macOS arm64, and macOS Intel.
- **Distribution**: Source builds support `cargo run --release`, `cargo build --release --locked`, and `cargo install --path crates/app --locked`. When a GitHub Release is published, it provides `install.sh` for Linux/macOS, `install.ps1` and `poqi-installer.cmd` for Windows, and archives for all four release targets. Each archive includes generated third-party Rust licenses and a version-guarded appendix for bundled native source. The Windows installer adds the user-local bin directory to PATH; the Unix installer prefers an existing user bin on PATH and otherwise appends `~/.local/bin` to the detected shell profile. No native MSI/pkg/deb/rpm/package feeds exist yet.

| Engine | Async execution through `tokio-postgres`, statement timeout enforcement, PostgreSQL server cancellation, no automatic replay after an uncertain connection failure, streaming COPY helpers (UI integration pending). Query errors display the PostgreSQL server message and SQLSTATE rather than a generic db error. Requested, confirmed server cancellation produces no failure popup. Statement timeouts and unsolicited cancellations remain errors unless they race with a successfully delivered cancellation; PostgreSQL then confirms an abort but provides no locale-independent distinction between those causes. New SQL, refreshes and table selections invalidate older semantic requests. Blocking inference runs outside the async event loop and checks cancellation between batches. Defaults: `model_dir=models/granite-embedding-97m-multilingual-r2`, batch size 96, top-k 100, threshold 0.2. The score threshold is a strict minimum: no qualifying rows produces an empty result. Scores are similarities, not probabilities; numeric conditions still require SQL. Top-k limits returned rows, not the initial embedding work. |

## Known Gaps
- **Search**: Semantic re-ranking only works on ad-hoc `SELECT *` previews today. Fuzzy/command-palette search, ANN indexes, hybrid boosters, and related-table surfacing are still stubs.
- **CRUD**: Insert is still a placeholder and multi-table/aggregated ad-hoc result sets remain read-only; inline Update/Delete are limited to single-table queries.
- **Catalog depth**: FK/index/comment metadata still missing; no incremental refresh.
- **Export**: COPY backend is ready, but the UI button still reports "queued (stub)".
- **Multitasking**: Single active query; firing a new command requests cancellation of the previous one.
- **UI polish**: No context menus, command palette, multi-tab editor, or animated flourishes.

See `docs/future-vision.md` for roadmap items covering these gaps.

## Quick Start
1. **Install poqi**: build from source with `cargo install --path crates/app --locked`. When a version is available on [GitHub Releases](https://github.com/poqi-cli/poqi/releases), you can instead use its installer or put the archive's `poqi`/`poqi.exe` on your `PATH`.
2. **Choose a connection**: run `poqi`. The profile menu always opens; choose a saved profile, paste a URL, or fill in separate connection fields. The compact form is centered horizontally and vertically, with contextual key hints and errors shown only when needed. Connection details sits below the fields in both visual and Tab order. Enter on Connection details switches between URL and separate fields; elsewhere it connects. E edits a saved profile; failed setup returns to a prefilled form with a persistent safe error. New/edited profiles are always saved securely after connection and catalog loading succeed. Existing profile names stay fixed during editing. Passwords are visible while editing; saved URIs are encrypted with AES-256-GCM and a key held in the native credential store.

   For headless `--check-connection` only, explicit `--url URL` (or positional URL) / `--profile NAME` overrides the environment, which overrides the saved primary. Interactive startup always uses the menu; `--list-profiles` lists redacted saved connections. `--check-connection` tests login and `SELECT 1` without opening the TUI or downloading semantic models, returning nonzero on failure. It does not test catalog permissions. `--doctor` checks configuration only. Setup has a 15-second deadline, adjustable with `--connect-timeout 1..300`. See the [connection guide](connections.md) for input controls, TLS and troubleshooting.

   Before the first configuration import, `[db.primary]` can be supplied in `~/.config/poqi/config.toml` (Linux) or `%APPDATA%\poqi\poqi\config\config.toml` (Windows). TOML is imported into SQLite only once; subsequent edits are not reloaded. This primary is a fallback only for headless login checks; interactive connections are chosen in the profile menu.
3. **Run**:
   ```bash
   poqi
   ```
   To run directly from a source checkout instead:
   ```bash
   cargo run --release
   ```
4. **Navigate**:
- WASD / arrows move the panel selector; **F** focuses a panel, **Esc** backs out, and **Ctrl+C** quits unless the editor or semantic panel is focused (where it copies instead). The layout now keeps schemas on the left, stacks the Editor + Semantic Search duo across the top-right (Editor 2/3, Semantic 1/3), and dedicates the bottom-right to the results grid—`W`/`S` hops between rows (top trio → results → status). While the selector is active, pressing **A** or ← from the results panel immediately jumps back to the schema/table panel so you can bounce into table browsing without landing on the semantic pane first.
- In the editor, Alt+Enter, Shift+Enter, or F5 execute SQL, Ctrl+V pastes from the clipboard, Ctrl+C copies the highlighted selection (falling back to the full buffer), Tab inserts indentation (or indents every selected line), Shift+Tab removes leading spaces, Shift+arrows, Shift-click, or mouse drag extend the selection with visible highlighting, Enter accepts a selected completion or inserts a newline, the mouse wheel scrolls the viewport without moving the caret, PageUp/PageDown jump by a full viewport, completions appear automatically when the cursor moves, and clicking any row (gutter or body) jumps the caret there—blank rows materialize automatically and Shift-click keeps extending the selection.
- In the Semantic Search panel, the text box behaves just like a mini editor: arrows + WASD move the caret, Shift extends the selection, Tab/Shift+Tab indent or outdent, Ctrl+V pastes, Ctrl+C copies the buffer or selection, and mouse clicks/drags reposition the cursor. Type a natural-language description, then press **Enter** to fetch and rerank the focused table; results overwrite the grid in similarity order and the status bar reports how many rows matched plus the top cosine score.
5. **Optional semantic search** (off by default): enable Semantic runtime in Settings and save to begin model/runtime preparation.
   - After the main UI appears, enabled semantic search verifies/downloads Granite's backend-specific ONNX model and `tokenizer.json` into `<config-dir>/models/granite-embedding-97m-multilingual-r2`. Auto uses DirectML on supported Windows systems and CPU elsewhere. The GPU package is about 415 MB; the CPU setting selects the smaller INT8 package (about 124 MB). Sizes exclude ONNX Runtime. Only the selected model is downloaded; a GPU initialization fallback may reuse its FP32 model on CPU. All assets come from a pinned IBM Hugging Face revision and require matching embedded SHA-256 checksums. Custom directories remain custom cache locations for the supported model.
- ONNX Runtime 1.23.0 CPU binaries now download automatically into `<config-dir>/runtimes/onxxruntime/1.23.0/<platform>` (`windows-x86_64`, `macos-universal`, or `linux-x86_64`). We extract the single shared library we need (`onnxruntime.dll` / `libonnxruntime.so` / `libonnxruntime.dylib`), verify SHA-256 for both the downloaded archive and extracted runtime file, resume interrupted runtime archive downloads when the server supports ranges, and set `ORT_DYLIB_PATH`. An explicitly exported path is validated and loaded before bundled runtime preparation; it skips bundled runtime downloads. CPU stays CPU, Auto checks the custom runtime provider list, and GPU requires DirectML support. On Windows we additionally hydrate `<config-dir>/runtimes/onxxruntime/1.23.0/windows-x86_64` by pulling `onnxruntime.dll` + `onnxruntime_providers_shared.dll` from the `Microsoft.ML.OnnxRuntime.DirectML` 1.23.0 NuGet package (the same archive that bundles the DirectML flavor of ONNX Runtime) and `DirectML.dll` from the Microsoft.AI.DirectML 1.15.4 NuGet package; CPU preference simply skips the DirectML download, leaving just the two ONNX DLLs in the same folder and reusing them for fallback runs.
   - In the schema browser, landing on a table with an ordinary name fetches `SELECT * LIMIT <select-top limit>` (default 5000, adjustable in Settings with no engine cap). Use **Shift+F** for a manual preview (also required for control/bidi names), the wheel or scrollbar to move through large lists, and note that dimmed entries were auto-fetched already.
   - The Semantic Search panel now mirrors the editor experience: caret-aware scrolling, Shift selection, mouse clicks/drags, and clipboard shortcuts all work, the status block reports verification, download, and ranking phases with throttled progress text, and rotating hints nudge discovery when the panel is idle.
   - Results grid uses WASD or the mouse wheel for cell navigation (Shift variants fast-scroll). Press Backspace or Enter to enter inline edit mode; while editing, WASD/F/R feed the cell buffer instead of triggering navigation or refresh, Enter submits a changed value, Ctrl+N sets SQL NULL, and Esc cancels.

CLI helpers: `poqi --doctor` prints install/config/connection/semantic readiness, `poqi --show-config` prints the resolved config, `--keymap` selects an alternate profile. Semantic options are managed in Settings rather than command-line overrides.

## Implementation Notes

### Workspace & Flow
- `crates/app` handles bootstrap (config load, store init, profile selection, Docker generator, db connect, catalog hydrate) before launching `poqi_ui::run_app` with a catalog snapshot, channel pair for the engine worker, and a process-scoped semantic bootstrap coordinator.
- On exit, returning to the profile selector reuses the existing store, config, and semantic bootstrap coordinator without restarting the process.

### UI & Input
- Ratatui 0.30.2 drives layout + drawing (rounded borders, padding, scrollbars), `crossterm` supplies raw event polling, and WASD-first interactions are preserved through two layers: `PanelSelect` (choose window) and `PanelFocused` (send keystrokes to schema/editor/semantic/results/status panels). Always confirm the pinned Ratatui version before planning UI work so new widget features stay in scope.
- Panel layout: left-hand schema browser, top-right split (Editor + Semantic Search) over a bottom-right results grid. The semantic panel shares the same text widget as the SQL editor (caret tracking, selection, mouse/clipboard support) so both panes feel consistent.
- `KeymapEngine` translates config-driven bindings into logical actions so custom profiles can extend the default set without recompiling.
- Editor state tracks lines, cursor offsets, completion popups, and can auto-commit zero-score suggestions for exact matches.
- Results state remembers the query origin so post-edit refreshes either rerun the canonical `SELECT *`/stored SQL or issue a targeted identity-checked refresh for complex statements while keeping focus stable.

### Engine & Database
- `poqi_engine::DatabaseEngine` wraps `poqi_db::Database` (deadpool-postgres pool). Each query runs inside a transaction with `SET LOCAL statement_timeout=<config>` and converts rows into displayable strings, preserving SQL NULL separately from the literal text `"NULL"`. Unchanged cell edits issue no update; Ctrl+N sets SQL NULL while editing, and typing replaces its placeholder. Actual NULL is dimmed and italicized in the grid.
- Schema and relation names travel as a shared `QualifiedRelation` through browsing, CRUD and refresh. SQL quoting escapes each component independently, including embedded dots and double quotes.
- `CrudAction::SelectTop` and targeted row refreshes use read-only transactions. Editable rows require a selectable valid primary key, captured in exact binary form, plus the queried relation OID, `tableoid`, `ctid` and `xmin`. Writes and targeted refreshes validate that identity with bound parameters; writes require exactly one returned row before commit. Tables without eligible keys and ordinary inheritance parents remain read-only. Direct projected columns retain physical source names separately from display aliases. Only proven-safe single-table projections receive appended hidden identity fields; filters, LIMIT/OFFSET, locking clauses, aggregates, DISTINCT, expressions and other unsupported projections run unchanged and remain read-only. Schema-qualified custom types preserve exact quoted components, including dots and embedded quotes. SQL batches are rejected explicitly before execution. Views have no edit/delete identity. Result metadata retains the original query for refresh.
- COPY helpers (`copy_out_csv`, `copy_out_csv_into`) support backend export workflows; the UI button still shows a stub message until the piping UX is designed.

### Catalog & Search
- `poqi_catalog` loads schemas, ordinary/partitioned tables, views, materialized views, foreign tables and their columns on connect. Catalog fallback supplies columns absent from `information_schema`; privilege filtering and domain nullability are preserved. Foreign keys/indexes/comments remain future work.
- `CatalogSnapshot` feeds two places: schema browser (pre-populated map) and `search/completion`, which scores keywords/clauses/sources and offers predicate snippets per column (capped at 8 per table).
- The UI can re-crawl the catalog on demand: successful DDL executed via the editor flags the catalog as stale, and once the engine is idle it refreshes the schema tree, column detail panel, and completion metadata using the same catalog crawl.
- `search/semantic` wraps Granite's ONNX session and Hugging Face JSON tokenizer, CLS pooling and cosine scoring. `search/fuzzy` and `search/ranker` remain placeholders.

### Store & Configuration
- `poqi_store` keeps data under `ProjectDirs::data_local_dir()/store/poqi.sqlite`, using bundled SQLite so binaries remain self-contained. Profile names remain readable; complete URIs and the db.primary setting are encrypted with AES-256-GCM. A random per-store key lives in Windows Credential Manager, macOS Keychain, or persistent Linux Secret Service; missing/unavailable keys fail closed while saved connections remain; an empty store can recreate a missing key. Current encrypted stores reopen without an upgrade; unsupported older schemas or plaintext records fail explicitly. The same database now has a `settings` table where theme, keymap profile, semantic knobs, and UI timing constants (tick rates, mouse scroll speed, status lifetimes, etc.) live.
- SQLite is authoritative after the initial TOML configuration load. Configuration loads before UI defaults are seeded. Persisted settings take precedence; DB defaults, primary connection and keymap definitions round-trip with UI/search settings. `AppConfig::save()` mirrors non-secret configuration to TOML, omitting db.primary. An initial TOML primary is removed only after verified encrypted persistence. `POQI_CONFIG_DIR` overrides configuration files but does not independently redirect the profile store.
- Startup uses only poqi data/config directories. It does not copy, inspect or upgrade previous application stores or caches.
- Environment overrides use only `POQI_DATABASE_URL`, `POQI_CONFIG_DIR`, `POQI_RESULTS_HORIZONTAL_SCROLLBAR` and `POQI_GLYPHS`. Docker test controls use `POQI_ENABLE_TESTCONTAINERS` and `POQI_TESTCONTAINERS_PG_TAG`.
- `[search]` settings control the semantic pipeline: `model_dir` (relative to the config dir by default), `semantic_batch_size`, `semantic_top_k`, `semantic_score_threshold`, and `semantic_title_column` feed the live panel today, while `semantic_dim`, `ann_engine`, and `rebuild_on_start` are future ANN settings. The dimension control is labelled accordingly and does not invalidate embeddings. Resolved values are kept in SQLite; use Settings to change runtime and ranking preferences.

### Observability & Recovery
- `poqi_observability` installs a `tracing` subscriber with env-filter control; bootstrap + engine paths emit structured logs.
- User-facing errors appear in the status bar (auto-dismiss after ~6s). Authentication failures bounce the user back into the profile form without restarting.
- Dispatched connection failures return without waiting for reconnection or replaying the operation. Worker cancellation uses one five-second deadline across registration, delivery and settling; failure to confirm completion reports an unknown outcome.

## Testing & Quality Gates
| Command | Purpose |
| --- | --- |
| `cargo fmt --all -- --check` | Enforce Rustfmt style. |
| `cargo clippy --workspace --all-targets --locked -- -D warnings` | Keep the workspace lint-clean (pedantic enabled). |
| `cargo test --workspace` | Run unit + integration tests; respects `POQI_ENABLE_TESTCONTAINERS=1` for Docker-backed suites. |
| `cargo audit` | Check `Cargo.lock` against RustSec advisories before release. |
| `./scripts/generate-third-party-notices.ps1 -TargetTriple <triple> -OutputPath <file>` | Generate the fail-closed Rust and bundled-native license report used by release archives. |

CI runs Ubuntu fmt, locked workspace Clippy/tests with digest-pinned PostgreSQL, cargo audit, CLI help, installer dry runs, and immutable workflow-reference checks. A separate native credential-store matrix covers Linux, Windows, macOS ARM64, and macOS Intel. Its Linux job runs the Store API inside Tokio, checks missing and locked-store failures, and verifies both directions of compatibility between the previous synchronous and current asynchronous Secret Service providers in an isolated session. Release publication requires these reusable workflows for the exact source SHA and successful extraction/smoke checks for every package, including its third-party notice file; Linux also tests the extracted binary against PostgreSQL. Windows package smoke checks help/version, with native storage covered separately. A specific commit is accepted only when its hosted runs succeed. Optimized builds run only when packaging releases.

Publication is restricted to a merged same-repository pull request from `dev` into `main` in `poqi-cli/poqi`. The stable application version in `crates/app/Cargo.toml` determines `v<version>`; update it and `Cargo.lock` before merging. An existing tag for another commit fails instead of being moved. The workflow creates a tag and GitHub Release only after the exact merged commit passes validation and packaging. Direct pushes, other branches, forks, and unmerged pull requests cannot publish through this workflow. `CHANGELOG.md` links to the resulting GitHub Releases history.

Linux uses keyring's asynchronous Secret Service provider with zbus's `async-io` runtime. Complete native credential operations run on a short-lived scoped operating-system thread, outside the entered Tokio runtime, and the caller waits for the result to preserve the synchronous Store API. The locked Linux application graph contains no `dbus-secret-service`, `dbus`, or `libdbus-sys` dependency; release checks must keep verifying that condition before the removed D-Bus native appendix remains valid.
