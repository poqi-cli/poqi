# Connecting to PostgreSQL

Use a running PostgreSQL server and an account that can access your database. Docker is only required for the optional demo generator, not for connecting to an existing database.

## Interactive connection

Run `poqi` in an interactive terminal. The profile menu always opens, regardless of environment URLs or a saved primary connection. Create a connection using a full PostgreSQL URL or separate host, port, user, password and database fields. The form keeps the URL path available for TLS and other advanced connection options.

The form supports cursor movement, Home/End, Delete/Backspace, paste and long-field scrolling. Tab/Shift+Tab or up/down switch fields, Space changes toggles, Ctrl+A clears the active field, and Enter connects. On the Connection details row, Enter or Space switches between URL and separate fields. Use a terminal of at least 60 columns and 24 rows; a smaller window asks you to resize while retaining your entries. Passwords are visible in both URL and separate-field editing. Successful connections are always saved securely. The complete URI is encrypted in SQLite with a key held by the operating system credential store.

Enter connects and loads the catalog. Only then is a new or edited profile saved. A failed attempt keeps its fields, input mode and a persistent actionable error, so you can correct the connection and retry. If secure saving fails, the form retains its fields for retry; it never falls back to plaintext storage. Edit an existing profile with E in the profile menu; its name stays fixed. Create another profile to use a different name. Deleting a profile does not delete the PostgreSQL database. Long profile lists scroll to keep the selection visible.

## Saved credentials

Connection URIs and the primary connection use AES-256-GCM encryption. Every write uses a fresh nonce, and authenticated context binds the ciphertext to its store, record type, and identity. The per-database key is stored in Windows Credential Manager, macOS Keychain, or Linux Secret Service. Linux needs an available, unlocked Secret Service; there is no unencrypted fallback. Profile names and ordinary settings remain readable in SQLite.

Only the current encrypted storage format is supported. Unsupported schemas, plaintext records, malformed envelopes, and authentication failures fail explicitly. A missing key fails closed while any encrypted connection remains; only an empty store can create a replacement key. The application does not inspect or import previous application directories. Copying SQLite alone to another OS/user account does not transfer its key; without that key, saved connections cannot be decrypted. This does not protect against arbitrary code running as the same OS user. Removing plaintext from the active config does not establish forensic erasure from storage-device history or external backups.

Encryption protects stored data; passwords still appear in the editing form as requested. Headless login checks do not save supplied URLs.

New demo databases bind only to `127.0.0.1`, use a fresh cryptographically random password per container, and pull a digest-pinned PostgreSQL image. Existing demo containers are not changed; recreate them or rotate their passwords if they were generated by a version using the shared default password.

## CLI choices

| Command | Behavior |
| --- | --- |
| `poqi` | Always opens the profile menu. |
| `poqi --list-profiles` | Prints saved names and redacted URLs, then exits. |
| `poqi --check-connection --profile local` | Tests login and `SELECT 1`, then exits without the TUI or model downloads. |
| `poqi --check-connection --url 'postgresql://user@localhost:5432/app'` | Tests an explicit URL. A positional URL is also accepted for login checks. |
| `poqi --connect-timeout 30` | Opens the menu and allows 30 seconds for connection/catalog setup. Default is 15; range is 1–300. |
| `poqi --doctor` | Reports local configuration; does not perform a login or network test. |

`--check-connection` returns exit code 0 on success and nonzero on failure. It needs an explicit URL/profile, environment URL or saved primary; it never opens an interactive selector. It verifies connectivity and authentication, not catalog permissions or application-specific SQL privileges. Normal browsing still requires an interactive terminal; this is not a command-line SQL batch runner.

For headless login checks only, connection priority is **explicit URL or profile → POQI_DATABASE_URL → saved primary**. An empty environment variable is an error and does not fall back. Explicit choices are mutually exclusive and require `--check-connection`. Interactive browsing always uses the menu selection.

## Environment examples

PowerShell:

```powershell
$env:POQI_DATABASE_URL = 'postgresql://app_user:example_password@localhost:5432/app_db'
poqi --check-connection
```

macOS/Linux:

```sh
export POQI_DATABASE_URL='postgresql://app_user:example_password@localhost:5432/app_db'
poqi --check-connection
```

Replace example values with your actual connection. The separate-fields form encodes URI components for you; if you compose a URL yourself, encode reserved characters in credentials and database names. Prefer the interactive form when you do not want a credential-bearing command in shell history or process arguments. Environment-provided connections are not automatically copied to the profile store.

## TLS

Connections require TLS by default and verify the server certificate chain and hostname against the operating system's trusted roots. This applies to the connection form and to URLs or keyword DSNs that omit `sslmode`. URL modes `require` and `verify-full` also require verified TLS.

An explicit `sslmode=prefer` permits plaintext fallback when the server refuses TLS; if TLS is offered, its certificate must still pass verification. `sslmode=disable` explicitly selects plaintext. Use these compatibility modes deliberately. App-generated loopback demo databases use `disable` because their PostgreSQL image does not configure TLS.

Supplying `sslrootcert` replaces the native trust roots with that CA bundle and requires certificate-chain and hostname verification. It forces TLS even with `prefer` and cannot be combined with `disable`.

Example using a trusted CA file, with paths represented as URL query parameters:

```text
postgresql://user@db.example:5432/app?sslmode=require&sslrootcert=C%3A%2Fcerts%2Fca.pem
```

Use `sslcert` and `sslkey` together for client certificates. Keep advanced TLS options in URL mode. TLS file extraction and `verify-full` normalization are URL-based; not all libpq keyword-DSN options are supported. Unsupported SSL modes are rejected.

## Troubleshooting

- **User/password error:** correct the credentials and check the server's access rules.
- **Database missing:** check the database name and account access.
- **Connection refused/unreachable:** check host, port, PostgreSQL availability, VPN and firewall routing.
- **TLS error:** check the SSL mode, trusted CA, hostname and paired client certificate/key files.
- **Setup timed out:** check reachability; allow longer with `--connect-timeout` for a slow server or large catalog.
- **Unexpected database:** return to the profile menu and select or edit the intended connection.
- **Secure saving failed:** unlock the operating system credential store, check local storage permissions, and retry with the retained form.

TOML is imported only once into SQLite. An initial TOML primary is removed from the active config only after encrypted persistence succeeds. Changing TOML later does not replace a saved primary; that primary is used only as a fallback for headless login checks. Interactive startup always opens the profile menu.

Semantic search is off by default. Enable Semantic runtime in Settings and save to start model/runtime preparation. Saved runtime choices are remembered. Cached files are retained.
